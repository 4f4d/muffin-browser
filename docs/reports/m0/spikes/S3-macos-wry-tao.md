## Recommended boundary

Start with the shared WRY/TAO calls for basic navigation, geometry, downloads and focus. Keep three native adapters behind internal policy and event types for metadata-rich decisions, native input ordering, per-engine permissions, download progress, lifecycle and window ownership. Windows needs the existing engine SDK bindings (`webview2-com` and `windows`) as direct dependencies when Muffin calls them. Linux already pins GTK and WebKitGTK bindings in the fixture. The enabled `v2_34` bindings are older than system WebKitGTK 2.52.6. Newer native hooks need explicit binding and runtime checks. Darwin can use `objc2-app-kit`, `objc2-web-kit` and `block2` rather than raw selectors for methods the bindings expose. Composing an Objective-C delegate or Win32 message/COM handler is native interop. Reserve it for hooks whose bound API and WRY ownership permit it. Keep unsupported selectors/private APIs out of the dependency plan. [Pinned code and official SDK references](../evidence/continuation-s3-source.txt)

Normalize notifications and permissions only when native hooks supply the request metadata required for the policy. Keep committed top-level URL, opener identity, frame role, engine view identity, and document generation distinct. A failing browser process and a recoverable renderer are different native events. Do not recreate a privileged view from remote metadata. [S1 security assessment](../S1_FOLLOW_UP_SECURITY.md), [S2a](S2a-macos-wry-tao.md)
