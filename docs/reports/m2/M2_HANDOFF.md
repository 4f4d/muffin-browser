# M2 — Tabs, windows and session lifecycle

The macOS development milestone adds native tab and window management. A private local instance socket forwards credential-free web links to the running browser. The window and tab owner retain navigation metadata and recreate a discarded view on selection. Session snapshots contain tab titles, addresses, selection and pinning. The current development guard allows up to eight windows and 100 tabs per window. [Native shell](../../../crates/muffin/src/main.rs), [tab model](../../../crates/muffin/src/tabs.rs), [session store](../../../crates/muffin/src/session.rs), [instance endpoint](../../../crates/muffin/src/instance.rs)

- The clean checkout at the recorded source commit passed `just verify` on Apple Silicon macOS 15.8.3. It ran 83 status and pin tests, one fixture test, 10 frontend tests, and 18 Rust tests. npm audit reported zero vulnerabilities. The two RustSec warnings still map to dependencies outside the Apple Silicon target graph. The release binary rejected test control. [Verifier receipt](../platform/m2/macos-arm64-verifier.json)
- Native loopback exercised creating, switching, pinning, reordering, duplicating, closing and reopening tabs. It observed background unload and reload on selection, separate navigation in a second native window, a second process forwarding a web link and exiting, and both windows returning after a graceful restart. It retained the original distinct-origin navigation, native Stop, file URL and untrusted-content checks. The fixture also attempted an unsolicited popup, and the server received no popup request. [Native receipt](../platform/m2/macos-arm64-native-smoke.json)
- The independent reviewer identified stale discard checks, recovery-budget resets and corrupt-session handling. The fixes bind discard results to a request and WebView generation, recheck native capture and loading, reset the recovery budget for explicit history commands, and preserve malformed session files when recovering. A local socket test reproduced an early rejection when an accepted connection inherited nonblocking mode, then passed with blocking I/O and a bounded timeout. The native dark capture shows the active tab and controls without the bright rim. An independent visual reviewer inspected the capture. The screenshot covers the chrome WebView. ## Engineering work still open

Unexpected WebContent termination and recovery, actual keyboard-focus visuals and full-window composition require further evidence. The popup path can route eligible links from a current opener to a separate tab. Real user-initiated popup behavior, opener-dependent sign-in and system default-browser registration remain qualification work. The native loopback used pages without media or capture, so media-preservation behavior has source checks and awaits a dedicated scenario.
