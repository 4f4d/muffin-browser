## Print verification rationale

The WebKit PDF export path and AppKit print path are separate. The print fixture uses the same window-based WebKit operation as the browser's Print control. It selects AppKit's Save Job disposition with a destination inside the disposable control directory, rechecks that disposition on the operation, and disables the print and progress panels. The test waits for a PDF trailer before examining the file. Native print-panel interaction was exercised in the later follow-up below. The two earlier print attempts produced an incomplete stream or timed out. [Print adapter](../../../crates/muffin/src/pdf.rs), [fixture check](../../../tests/native/run_smoke.py), [attempts](../../BLOCKERS.md#m4-integration-attempts), [Apple print operation](https://developer.apple.com/documentation/appkit/nsprintoperation)

Poppler extracted the expected fixture phrase, and the independent reviewer rechecked the page count, text, source identity, and file hash. - The initial exit review withheld M4 sign-off. Restarting eligible downloads, opening completed files, and setting and verifying the download location remain open. [Plan](../../PLAN.md#downloads-and-page-tools)
- The content view denies media permission requests. WRY's pinned permission handler exposes the permission kind and drops the requesting origin and frame. Apple exposes those fields through `WKUIDelegate`. The development bundle needs camera and microphone usage descriptions before capture can be tested. The reviewed public `WKWebView` API exposes suspension of all media playback. Audio-only mute remains unverified. [Content WebView](../../../crates/muffin/src/main.rs), [Apple permission callback](https://developer.apple.com/documentation/webkit/wkuidelegate/webview(_:requestmediacapturepermissionfor:initiatedbyframe:type:decisionhandler:)), [Apple playback suspension](https://developer.apple.com/documentation/webkit/wkwebview/setallmediaplaybacksuspended(_:completionhandler:)), [open decisions](../../DECISIONS_PENDING.md)
