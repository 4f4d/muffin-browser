# M5 — macOS privacy and security

## Scope

Private windows, website data removal, unsupported-protocol handling and the TLS error surface are the macOS development scope. The private-window shortcut is Shift–Command–N. The decision record explains the WebKit store lifetime, the role of the regular profile, and what happens to a file saved from a private window. [Privacy decision](../../adr/0006-macos-private-window-and-website-data.md)

## Verified macOS engineering exit

- Two tabs in one private window shared cookie, localStorage and Cache Storage markers. A second private window and the regular store could not read them. A regular website-data clear removed its own markers and left the private markers available to the original private window. A fresh private window started with empty state after close. The fixture verified zero private URL entries in regular SQLite history, bookmarks and shortcuts, no private windows or URLs in the serialized session, the restored regular window’s identity, and routing of an external instance URL to regular browsing. [Native receipt](../platform/m5/macos-arm64-m5-native-smoke.json)
- An explicitly saved private fixture file survived the window close. It retained its quarantine attribute and stayed out of the regular Downloads list. An unsupported protocol input was blocked. A self-signed loopback server received zero HTTP requests after WebKit rejected its certificate, and the trusted error surface offered a route back to Start. [Native receipt](../platform/m5/macos-arm64-m5-native-smoke.json), [native private window](../platform/m5/macos-arm64-private-start.png), [native error surface](../platform/m5/macos-arm64-secure-connection-error.png)
- The first clean compact capture passed the privacy isolation checks and failed when it expected a specific regular window to be frontmost after restart. The corrected test checks every saved window and focuses the unique regular control window before asserting its native restoration. The subsequent capture passed and displayed all eight browser actions in the 640-point layout. [First capture receipt](../platform/m5/macos-arm64-first-multiwindow-capture.json), [passing capture receipt](../platform/m5/macos-arm64-m5-native-capture.json), [compact actions](../platform/m5/macos-arm64-chrome-compact-actions.png)
- The full local verifier passed on clean `69c8625a44fda0216cea2c2faa697b9174731757`. It ran 83 tooling tests, one native fixture unit test, 26 UI tests, 45 Rust tests, type checking, source formatting, Clippy, dependency audits, debug and release builds, release debug-control exclusion and native smoke. Cargo audit recorded two allowed GTK-related warnings. The independent reviewer reviewed the implementation and reran the portable verifier on the exact source. The hosted verifier passed on that source. This clears macOS M5 engineering and opens M6. [Local verifier receipt](../platform/m5/macos-arm64-m5-verifier.json), [hosted run](https://github.com/4f4d/muffin-browser/actions/runs/45062716840)

## Qualification boundaries

- The verifier uses a disposable regular WebKit store and a disposable SQLite profile. The test compares cookies, localStorage and Cache Storage, opens two private windows, and restarts the normal session. A separate forensic examination of OS or engine caches and crash diagnostics has not been performed. The owner-operated M0b matrix remains deferred. [Native fixture](../../../tests/native/run_smoke.py), [deferred qualification](../../adr/0002-macos-first-implementation-and-deferred-qualification.md)
- Download quarantine evidence covers the metadata preserved on an approved loopback download. Gatekeeper, signed-app launch, private-mode capture permissions, third-party cookies and packaged-app behavior remain qualification work. [M0 capabilities](../m0/S4_EVERYDAY_MATRIX.md)
- WebKit blocks automatic JavaScript windows through its engine preference. Muffin confines requests reaching WRY’s window callback to HTTP and HTTPS and routes them to the opener’s window. WRY does not give Muffin frame or activation provenance. Open-site and sign-in popup compatibility still need qualification. [Apple popup preference](https://developer.apple.com/documentation/webkit/wkpreferences/javascriptcanopenwindowsautomatically), [M0 popup evidence](../m0/spikes/S2a-macos-wry-tao.md)
- Content blocking and HTTPS-first need further validation. The native rule-list feasibility fixture did not exercise production rules, licensing, false positives, exceptions or overhead. The application defaults bare hostnames to HTTPS and offers no upgrade and fallback policy for explicit HTTP navigation. Unsupported external protocols stay blocked. [S4 feasibility](../m0/S4_EVERYDAY_MATRIX.md), [open decisions](../../DECISIONS_PENDING.md)
